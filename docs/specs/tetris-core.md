# 테트리스 코어 스펙

## 1. 개요

### 1.1 프로젝트 목표
- **단기**: 1인용 마라톤 모드 테트리스 구현
- **장기**: 최대 100인 동시 대전 가능한 멀티플레이어 테트리스

### 1.2 기술 스택
- **언어**: Rust (Edition 2024)
- **그래픽**: SDL3 (`sdl3` crate)
- **렌더링**: 이미지 미사용, 단색 사각형 기반

### 1.3 준수 표준
- 테트리스 가이드라인 (Tetris Guideline)
- SRS (Super Rotation System)

---

## 2. 플레이필드

### 2.1 크기
| 항목 | 값 |
|------|-----|
| 너비 | 10 셀 |
| 가시 높이 | 20 셀 |
| 버퍼 존 | 20 셀 (상단, 비가시) |
| 총 높이 | 40 셀 |

### 2.2 좌표계
- 원점 (0, 0): 좌측 하단
- X축: 우측으로 증가 (0-9)
- Y축: 상단으로 증가 (0-39)

### 2.3 가시 영역
- 0-19행: 메인 플레이 영역
- 20행: 부분 표시 (스폰 힌트)
- 21-39행: 숨김

## 3. 테트로미노

### 3.1 종류 (7-bag)

| 이름 | 색상 | 형태 |
|------|------|------|
| I | 시안 (#00FFFF) | ████ |
| O | 노랑 (#FFFF00) | ██ / ██ |
| T | 보라 (#800080) | ███ / _█_ |
| S | 초록 (#00FF00) | _██ / ██_ |
| Z | 빨강 (#FF0000) | ██_ / _██ |
| J | 파랑 (#0000FF) | █__ / ███ |
| L | 주황 (#FFA500) | __█ / ███ |

### 3.2 스폰 규칙
- 위치: 상단 중앙 (21-22행)
- 방향: 수평 (회전 상태 0)
- I, O: 정중앙 정렬
- J, L, S, T, Z: 좌측 정렬

### 3.3 7-bag 랜덤 생성
- 7개의 테트로미노를 한 세트로 섞음
- 세트 내에서 중복 없이 순차 배출
- 세트가 비면 새로 생성하여 섞음

## 4. 회전 시스템 (SRS)

### 4.1 회전 상태
| 상태 | 설명 |
|------|------|
| 0 | 스폰 상태 |
| R | 시계방향 90° |
| 2 | 180° |
| L | 반시계방향 90° |

### 4.2 Wall Kick 테이블

#### J, L, S, T, Z 미노
| 회전 | Test 1 | Test 2 | Test 3 | Test 4 | Test 5 |
|------|--------|--------|--------|--------|--------|
| 0→R | (0,0) | (-1,0) | (-1,+1) | (0,-2) | (-1,-2) |
| R→0 | (0,0) | (+1,0) | (+1,-1) | (0,+2) | (+1,+2) |
| R→2 | (0,0) | (+1,0) | (+1,-1) | (0,+2) | (+1,+2) |
| 2→R | (0,0) | (-1,0) | (-1,+1) | (0,-2) | (-1,-2) |
| 2→L | (0,0) | (+1,0) | (+1,+1) | (0,-2) | (+1,-2) |
| L→2 | (0,0) | (-1,0) | (-1,-1) | (0,+2) | (-1,+2) |
| L→0 | (0,0) | (-1,0) | (-1,-1) | (0,+2) | (-1,+2) |
| 0→L | (0,0) | (+1,0) | (+1,+1) | (0,-2) | (+1,-2) |

#### I 미노
| 회전 | Test 1 | Test 2 | Test 3 | Test 4 | Test 5 |
|------|--------|--------|--------|--------|--------|
| 0→R | (0,0) | (-2,0) | (+1,0) | (-2,-1) | (+1,+2) |
| R→0 | (0,0) | (+2,0) | (-1,0) | (+2,+1) | (-1,-2) |
| R→2 | (0,0) | (-1,0) | (+2,0) | (-1,+2) | (+2,-1) |
| 2→R | (0,0) | (+1,0) | (-2,0) | (+1,-2) | (-2,+1) |
| 2→L | (0,0) | (+2,0) | (-1,0) | (+2,+1) | (-1,-2) |
| L→2 | (0,0) | (-2,0) | (+1,0) | (-2,-1) | (+1,+2) |
| L→0 | (0,0) | (+1,0) | (-2,0) | (+1,-2) | (-2,+1) |
| 0→L | (0,0) | (-1,0) | (+2,0) | (-1,+2) | (+2,-1) |

#### O 미노
- Wall kick 없음 (회전해도 형태 동일)

### 4.3 180도 회전
- 0↔2, R↔L 직접 전환 지원
- Wall kick: 90도 회전 2회 적용과 동일한 결과

## 5. 게임 메커니즘

### 5.1 중력 (Gravity)
- 레벨별 낙하 속도 (프레임/셀)
- 레벨 1: 1초/셀
- 레벨 15: 약 0.1초/셀
- 레벨 20+: 20G (즉시 낙하)

### 5.2 락다운 (Lock Down)
- **방식**: Extended Placement (Move Reset)
- **딜레이**: 0.5초 (500ms)
- **리셋 조건**: 이동 또는 회전
- **리셋 제한**: 최대 15회
- **강제 잠금**: 리셋 횟수 초과 시 즉시 잠금

### 5.3 홀드 (Hold)
- 현재 미노를 홀드 슬롯에 저장
- 홀드 슬롯에 미노가 있으면 교환
- 한 미노당 1회만 홀드 가능 (잠금 후 리셋)

### 5.4 라인 클리어
- 가로줄이 완전히 채워지면 제거
- 동시에 여러 줄 제거 가능 (1-4줄)
- 제거 후 상단 블록이 아래로 이동

### 5.5 게임 오버
- 새 미노 스폰 시 기존 블록과 겹침
- 또는 미노가 가시 영역 밖에서 잠김

## 7. 조작 체계

### 7.1 키 매핑

| 액션 | 기본 키 |
|------|---------|
| 좌측 이동 | ← (Left Arrow) |
| 우측 이동 | → (Right Arrow) |
| Soft Drop | ↓ (Down Arrow) |
| Hard Drop | Space |
| 시계방향 회전 | ↑ (Up Arrow) 또는 X |
| 반시계방향 회전 | Z |
| 180도 회전 | A |
| 홀드 | C 또는 Shift |
| 일시정지 | Escape |
| 재시작 | R |

### 7.2 DAS/ARR 설정
- **DAS (Delayed Auto Shift)**: 167ms (10프레임 @60fps)
  - 키를 누르고 있을 때 자동 반복 시작까지의 지연
- **ARR (Auto Repeat Rate)**: 50ms (3프레임 @60fps)
  - 자동 반복 간격

### 7.3 Soft Drop
- 속도: 기본 낙하 속도의 20배
- 점수: 이동한 셀당 1점

## 9. 렌더링 스펙

### 9.1 화면 구성

```
┌─────────────────────────────────────┐
│  HOLD    │  PLAYFIELD  │   NEXT    │
│  [미노]  │  10 × 20    │  [미노1]  │
│          │  + 고스트   │  [미노2]  │
│          │             │  [미노3]  │
│  SCORE   │             │  [미노4]  │
│  LEVEL   │             │  [미노5]  │
│  LINES   │             │           │
└─────────────────────────────────────┘
```

### 9.2 윈도우 설정
- 기본 해상도: 1280 × 720
- 창 크기 조절: 지원
- 전체화면: 지원 (F11)

### 9.3 셀 크기
- 기본: 30 × 30 픽셀
- 화면 크기에 따라 동적 조절

### 9.4 색상 팔레트

| 요소 | 색상 (RGB) |
|------|------------|
| 배경 | #1a1a2e |
| 그리드 | #16213e |
| 고스트 | 미노 색상 50% 투명도 |
| 잠긴 블록 | 미노 색상 80% 밝기 |

### 9.5 사운드
- 초기 버전: 미포함
- 향후 확장 시 추가 예정

### 9.6 리소스 최적화 (멀티플레이어 대비)
- 더티 플래그 기반 부분 렌더링
- 변경된 셀만 다시 그리기
- 상태 직렬화를 위한 최소 데이터 구조
